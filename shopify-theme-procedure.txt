Работеща процедура за промени по Shopify тема (пример: test-avalon.myshopify.com)

================================================================================
FROZEN PRODUCT/CART CONTRACT (frontend → CP)
================================================================================

Product POST fields (exact):
  payload_version, source, unicid, shop_domain, shop_permanent_domain,
  variant_id, quantity

Cart POST fields (exact):
  payload_version, source, unicid, shop_domain, shop_permanent_domain,
  cart_identity

payload_version = 2. Product source = product; Cart source = cart.
Cart identity is the unmodified cart.token from the final stable cart.js
snapshot. CP reconstructs all Cart lines, quantities, catalog data,
collections, money, and currency authoritatively through Storefront Cart lookup.

Trust boundary:
  ALL frontend fields are UNTRUSTED.
  CP must validate every field server-side.
  Domains/unicid/currency/money are public context, not authentication.

================================================================================
Local financing minimum (uni_min_price) - local eligibility gate
================================================================================

Theme setting (canonical UniCredit settings block in step 5 below):
  id: uni_min_price   type: number   default: 50

Unit: whole major units of the store currency. Shopify money values
(variant price, Liquid cart.total_price, cart.js total_price) are minor units
(1/100 for the supported currencies), so the threshold is compared as
uni_min_price x 100. All comparisons are integer comparisons.

Local gate (decided in the browser, before any CP request):
  selected variant price < uni_min_price  -> button hidden, no CP POST
  cart total             < uni_min_price  -> button hidden, no CP POST
  amount >= uni_min_price                 -> existing eligibility continues

Shopify "number" settings cannot enforce positive integers, so the value is
validated defensively in Liquid and again in JS: missing, zero, negative,
fractional or non-numeric configuration falls back to 50. The gate never
falls back to 0/unlimited.

This gate is local only. It does NOT change the frozen CP contracts: no
uni_min_price, price, cart amount or eligibility result is ever POSTed.

Deployment: config/settings_schema.json is intentionally NOT committed, so an
existing merchant theme must add the uni_min_price entry manually to the
UniCredit settings block from this file (step 5). No CP deployment is needed.

================================================================================
Theme compatibility policy
================================================================================

This integration is distributed to unknown Shopify stores and themes.
Do NOT assume Dawn, Horizon, or any specific theme layout.

Resolution priority:
  1. Shopify API / runtime state
     (cart.js, variants/{id}.js, products/{handle}.js, Shopify.currency, …)
  2. Platform-level form conventions
     (form[action*="/cart/add"], input[name="id"], input[name="quantity"], …)
  3. Generic defensive DOM selectors (validated; never arbitrary first match)
     e.g. input[name="quantity"], input[type="number"][name*="quantity"]
  4. Theme-specific selectors / wrappers (.shopify-section, Dawn layouts, …)
     — fallback ONLY, never primary architectural contract

When a generic selector can match more than one product context:
  validate association (form containment, form="<id>", unique page candidate).
  Do NOT pick document.querySelector(...) first match arbitrarily.

Product quantity follows this policy:
  - JET-compatible generic selectors first
    (input[name="quantity"], input[type="number"][name*="quantity"])
  - findProductForm() only disambiguates when multiple candidates exist
  - hidden/stale duplicates are dropped when a presented control exists
  - never arbitrary first match across multiple product contexts
Product price/ownership uses Ajax APIs; variant id prefers form[name=id].

Product currency and pricing are reconstructed by CP. Cart currency, discounts,
line totals, and final total are reconstructed by CP from Storefront authority.

Modal lifecycle:
  Product and Cart share one page-level active Uni flow (window.__UniTransport).
  Only one UniCredit modal may be active at a time.
  Body scroll lock/unlock is owned by the shared active flow.
  Closing an inactive modal must not alter page scroll.
  Iframe containment (Phase 8.2 theme-side):
    modal opens → loading UI → iframe created hidden
    iframe load is NOT authority to reveal
    trusted postMessage uni:ready → clear timeout, hide loading, show iframe
    no uni:ready within READY_TIMEOUT_MS (10000) → iframe stays hidden, safe parent error
  postMessage uni:ready / uni:close / uni:bank-redirect accepted only when:
    event.origin === new URL(CP_BASE_URL).origin   // derived from central config
    event.data.type === "uni:ready" | "uni:close" | "uni:bank-redirect"
    event.source === active iframe.contentWindow
  Trusted uni:bank-redirect (after SmartUCF URL validation):
    Product source → top-level SmartUCF navigation; Shopify cart untouched
    Cart source → POST {Shopify.routes.root}cart/clear.js (bounded ~2s), then navigate
    cart clear failure/timeout MUST NOT block SmartUCF redirect
    modal/Step 3 loader stays visible until navigation (no closeActive before assign)
  Close (X / Escape / uni:close) at loading|ready|timeout clears timeout, resets iframe,
  restores scroll, releases Product/Cart lock. Re-open starts a fresh attempt.

================================================================================
CP BASE URL — SINGLE SOURCE OF TRUTH (deployment packaging)
================================================================================

File:  assets/uni-transport.js
Value: CP_BASE_URL   ← change ONLY this for environment packaging

  DEV:        https://uni.avalonbg.com
  TEST:       <test CP base URL>
  PRODUCTION: <production CP base URL>

Derived automatically:
  allowed postMessage origin = new URL(CP_BASE_URL).origin
  DEV/TEST echo POST URL     = {CP_BASE_URL origin}/shopify/product-test

Do NOT put CP URL in Theme Editor / settings_schema.json.
Do NOT duplicate CP hostnames in Product/Cart JS.
Invalid CP_BASE_URL → fail safely (no modal, no POST).

Echo path /shopify/product-test is DEV/TEST ONLY.
Before production: set production CP_BASE_URL and replace echo path with
production CP routes if they differ.

================================================================================
FILES
================================================================================

snippets/
  uni-product-button.liquid
    - Custom Liquid (product page): {% render 'uni-product-button', product: product %}
    - requires settings.uni_status + settings.uni_unicid + product
    - embeds data-uni-collection-ids from product.collections (numeric IDs)
    - embeds data-uni-min-price + data-uni-variant-prices for the local minimum gate
  uni-cart-button.liquid
    - Custom Liquid (cart page): {% render 'uni-cart-button' %}
    - requires settings.uni_status + settings.uni_unicid
    - Liquid cart is NOT authoritative; JS uses cart.js on click
    - embeds data-uni-min-price; the local minimum gate uses cart.js on click

assets/
  uni-transport.js
    - CP_BASE_URL single source of truth (DEV/TEST/PRODUCTION packaging)
    - shared active flow, scroll ownership, Escape, postMessage hardening
    - normalizeCollectionIds() shared defensive normalizer
  uni-product-button.css / uni-product-button.js
  uni-cart-button.css / uni-cart-button.js
  uni_logo.svg

config/settings_schema.json
  UniCredit settings block (shared)

No Checkout integration / Shopify app / Shopify order creation.
No CP calculator / SmartUCF / order creation in theme.

8) Production installation / runtime verification checklist
   BEFORE production:
   [ ] Set production CP_BASE_URL in assets/uni-transport.js (one value)
   [ ] Replace temporary /shopify/product-test echo path with production CP routes if needed
   [ ] Confirm production URL is HTTPS and owned by UniCredit CP
   [ ] Confirm uni.avalonbg.com is absent from Product/Cart JS (only in CP_BASE_URL / docs)
   [ ] uni_status on + uni_unicid set in published theme settings
   [ ] Product Custom Liquid render present on product template
   [ ] Cart Custom Liquid render present on cart template
   [ ] uni-transport.js + product/cart assets deployed

   Product runtime:
   [ ] variant + quantity resolve via platform/generic selectors (not Dawn-only)
   [ ] quantity matches visible UI; multi-product pages do not pick arbitrary qty
   [ ] wrong-product variant cannot POST
   [ ] currency is presentment (matches Ajax amounts), not blind shop.currency
   [ ] products[].collection_ids present (array; may be empty)
   [ ] echo: source=product, products[1], total_price_cents
   [ ] uni_min_price gate: variant price below minimum -> button hidden, no POST

   Cart runtime:
   [ ] cart.js is source of truth (after quantity Ajax updates)
   [ ] final stable cart.js snapshot supplies the unmodified cart.token
   [ ] POST contains only the six Cart payload v2 fields
   [ ] empty cart → no POST
   [ ] no currency, products, totals, quantities, prices, or collection IDs sent
   [ ] uni_min_price gate: cart total below minimum -> button hidden, no POST

   Shared modal:
   [ ] only one Uni modal active (Product vs Cart mutual exclusion)
   [ ] overlay does not close; X / Escape / uni:close close
   [ ] body scroll restored exactly once on close
   [ ] inactive modal cannot alter scroll/DOM via postMessage

   Security/ops:
   [ ] treat all frontend payload fields as UNTRUSTED at CP
   [ ] no Shopify cart mutation from Uni theme scripts
   [ ] no calculator/SmartUCF/banking logic in theme
